# Architectural Decision Record (ADR): Обеспечение отказоустойчивости и масштабируемости InsureTech

## Контекст
Текущая архитектура представляет собой единую точку отказа (SPOF): одна зона доступности, единственный экземпляр БД на VM.
**Требования бизнеса:**
*   Доступность: 99.9%
*   RTO (Recovery Time Objective): 45 мин.
*   RPO (Recovery Point Objective): 15 мин.
*   География: Клиенты по всей РФ (требуется низкая задержка загрузки).

## Предлагаемое решение (To-Be)

Мы переходим к архитектуре **Single Region, Multi-AZ (Active-Active)**.

### 1. Вычислительные ресурсы (Kubernetes)
*   **Стратегия:** Кластер Kubernetes разворачивается поверх трех зон доступности (Availability Zones: A, B, C).
*   **Масштабирование:**
    *   **HPA (Horizontal Pod Autoscaler):** Автоматически увеличивает количество подов приложений при росте нагрузки (CPU/Memory/RPS).
    *   **Cluster Autoscaler:** Автоматически добавляет новые Node (VM) в кластер, если поды не помещаются на текущих узлах.
*   **Отказоустойчивость:** При отказе одной зоны (Zone Failure), Kubernetes автоматически перераспределяет поды в выжившие зоны. Сервис продолжает работу без ручного вмешательства.

### 2. База данных (PostgreSQL)
*   **Конфигурация:** Кластер PostgreSQL (Patroni или Managed Service) в конфигурации **1 Primary + 2 Standby**.
*   **Распределение:** Узлы БД разнесены по разным зонам доступности.
*   **Репликация:**
    *   Синхронная репликация (Quorum commit) гарантирует, что данные записаны минимум в 2 зоны перед подтверждением транзакции. Это обеспечивает **RPO ≈ 0**, что значительно лучше требуемых 15 минут.
*   **Failover:** Автоматическое переключение мастера занимает < 2 минут (RTO < 45 мин выполняется с запасом).
*   **Бэкапы:** WAL-логи непрерывно стримятся в S3 Object Storage для обеспечения Point-in-Time Recovery (PITR).

### 3. Сеть и доставка контента
*   **Load Balancer (L7):** Application Load Balancer распределяет входящий трафик между подами во всех зонах. Он же выполняет Health Checks.
*   **CDN (Content Delivery Network):** Для решения проблемы "медленной загрузки в регионах" статический контент (JS, CSS, изображения) выносится в CDN. Пользователи из Владивостока будут загружать интерфейс с ближайшего Edge-сервера, а не из Москвы.

### 4. Соответствие требованиям

| Параметр | Требование | Решение | Результат |
| :--- | :--- | :--- | :--- |
| **Доступность** | 99.9% | Multi-AZ (3 зоны) + L7 Balancer | **Выполнено** (Типичный SLA для Multi-AZ > 99.95%) |
| **RTO** | 45 мин | Auto-failover БД + K8s Self-healing | **Выполнено** (< 5 мин) |
| **RPO** | 15 мин | Sync Replication + WAL Archiving | **Выполнено** (~0 сек) |
| **География** | Быстрая загрузка | CDN | **Выполнено** |
